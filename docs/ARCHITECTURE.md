# Архитектура

## Компоненты

### Cloudflare Worker

Worker отдаёт внутренний пульт, проверяет команды, формирует сообщения длиной не более 950 Unicode-символов и предоставляет sender только два действия: получить outbox и подтвердить доставленные записи.

### `ZoomMeetingState` Durable Object

Хранит:

- обычную очередь и статусы `waiting` / `spoken`;
- дополнительные темы;
- отдельную очередь спикерской;
- idempotency-ключи `requestId`;
- последние сформированные тексты;
- outbox и подтверждения sender.

Изменения выполняются последовательно внутри Durable Object и сохраняются транзакцией. Одинаковый текст очереди разрешён: две записи «Вася 111» — это два выхода, а не раздвоение личности базы.

### `ZoomSharedTimerState` Durable Object

Хранит только общий таймер, ревизию, lease настольного исполнителя и отметку о выдаче финального звука. Частые запросы таймера не касаются состояния очереди.

Только один настольный Zoom-клиент получает роль исполнителя динамического индикатора и общего звука. Телефон может запустить таймер, а выбранный настольный клиент покажет отсчёт и передаст семь гудков участникам.

### Private Cloudflare R2

Книжная база хранится в `zoom-library/current.json`. Перед публикацией нового варианта текущая версия копируется в `zoom-library/previous.json`. Панель принимает Markdown-файлы, проверяет дубли, пропуски и пустые записи, а затем публикует единый JSON.

### Sender на VPS

Playwright открывает постоянную конференцию как отдельный участник с выключенными микрофоном и видео. Sender забирает outbox, отправляет сообщения по порядку и подтверждает только успешно отправленные ID.

### Control-agent

Отдаёт внешний веб-пульт и Home URL Zoom App, управляет Docker-контейнером sender и создаёт короткую защищённую сессию из проверенного `X-Zoom-App-Context`. Административная книжная загрузка скрыта от обычного Zoom App.

## Почему два Durable Object

Один общий объект создаёт «горячую точку»: таймер опрашивается часто, а очередь и объявления содержат заметно больше данных. Разделение уменьшает размер каждой операции, изолирует сбои и не даёт таймеру перегружать outbox.

## Чего здесь намеренно нет

- Telegram и его расписания;
- чтения входящего Zoom-чата;
- старого queue engine и webhook/ingest-маршрутов;
- общей базы пользователей разных групп;
- секретов в URL Worker или в репозитории.
