# Настройка группы

Главный файл — [`config/group.json`](../config/group.json). После изменения перезапустите тесты и заново разверните Worker.

## Основные поля

| Поле | Назначение |
|---|---|
| `appName` | Название в Worker и его пульте |
| `botDisplayName` | Рекомендуемое имя участника-бота |
| `timeZone` | Часовой пояс для текущего дня и ежедневных текстов |
| `messageLimit` | Итоговый предел сообщения; по умолчанию 950 |
| `meetingDays` | Раскрывашки дней, темы дня и доступная литература |
| `meetingButtons` | Общие кнопки и их тексты |
| `speaker` | Заголовок и вступление спикерской |
| `testMessage` | Безопасный текст тестовой отправки |

`contexts` у кнопки может содержать `meeting`, `speaker` или оба значения.

## Доступные идентификаторы литературы

- `big_book`
- `twelve_twelve`
- `living_sober`
- `daily_reflections`
- `as_bill_sees_it`
- `game_questions`

## Markdown-база

Один файл — один логический отрывок:

```text
Книги/
  Большая книга/
    001.md
    002.md
  12 шагов и 12 традиций/
    001.md
  Жить трезвыми/
    001.md
  Ежедневные размышления/
    01.01.md
    02.01.md
  Как это видит Билл/
    001.md
  Вопросы игры/
    001.md
    500.md
```

YAML front matter не отправляется в Zoom. Для ручной смысловой границы используйте:

```md
Первая часть.

<!-- zoom-part -->

Вторая часть.
```

Если готовая часть всё равно длиннее лимита, Worker делит её по абзацам, предложениям и словам. Надписи `Часть 1/2` не добавляются. Заголовок книги и номер добавляются один раз, если их ещё нет в самом Markdown.

## Изображения

Иконка Zoom App и оформление зала ожидания не берутся из `group.json`: это настройки конкретного Zoom-аккаунта. Нейтральные заготовки лежат в [`assets`](../assets), но группа должна загрузить своё изображение в Marketplace и отдельно оформить зал ожидания.
